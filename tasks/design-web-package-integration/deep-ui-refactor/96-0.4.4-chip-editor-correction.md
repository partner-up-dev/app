# 0.4.4 Chip Editor Correction

## Objective & Hypothesis

Objective: upgrade `@partner-up-dev/design-web` from `0.4.3` to `0.4.4` and
correct downstream chip-editor usage after the package split `PuChipInput` and
`PuChipsEditor` responsibilities.

Hypothesis: app-side plain string-array chip collection editors should migrate
to `PuChipsEditor`, while richer per-label edit surfaces should compose
individual `PuChipInput` instances.

## Guardrails Touched

- Dependency boundary: consume `@partner-up-dev/design-web@0.4.4` through the
  package root and package-shipped skill references.
- Agent skill boundary: do not hand-edit local skill copies. Verify the
  package skill through TanStack Intent.
- Product invariant: preserve PR preference editing and Form Mode preference
  selection/submission semantics.
- Type invariant: no local type shims and no package-private imports.

## API Reading

- `PuChipInput` intent is now editable single-chip input.
- `PuChipsEditor` intent is editable string-array chip collection with draft
  entry, add/remove events, and an optional `chip` slot.
- `PuChipsEditor` still defers suggestions and custom option listbox
  behavior, so Form Mode curated option selection and per-tag editing remain
  domain-owned `PuChipGroup` + `PuChip`/`PuChipInput` composition.

## Implementation Notes

- Upgraded `apps/frontend/package.json` and `pnpm-lock.yaml` to
  `@partner-up-dev/design-web@0.4.4`.
- Verified package skill discovery, load, and validation with TanStack Intent.
- Replaced old array-style `PuChipInput` usage in `PREditor.vue` with
  `PuChipsEditor`.
- Replaced the custom preference entry lane in
  `FormModePreferenceControl.vue` with per-label `PuChipInput` composition:
  existing custom labels are editable chip inputs, and a blank draft chip input
  adds new custom labels.
- Updated task-local migration docs and frontend shared UI guidance to reflect
  the corrected chip-editor boundary.

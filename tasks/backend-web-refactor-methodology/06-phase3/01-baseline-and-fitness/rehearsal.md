# Slice 01 Mental Rehearsal

## Subtask Preflight Matrix

| Subtask | Information to have in hand | Main fork / surprise | Cheapest sufficient proof |
| --- | --- | --- | --- |
| 01A promote truth | current source topology + governing docs | target rule is not live yet | source-linked doc diff labels compatibility window |
| 01B dependency matrix | owner/import inventory + allowed seams | OAuth/BI/legacy edge is intentional | reviewed matrix + named exception with removal condition |
| 01C choose mechanism | existing ast-grep config/rules + sample edges | syntax rule cannot model a graph relation | positive/negative fixture or deterministic parser output |
| 01D baseline/block | normalized finding set from two scans | shared-worktree drift changes the baseline | identical report runs + classified allowlist; no business diff |

## Simulated Flow

1. Record HEAD/status and discover that the historical baseline differs.
2. Promote only the stable target owner model, retaining current compatibility seams by name.
3. Run candidate rules in report mode.
4. Separate true new-edge prevention from historical cleanup.
5. If precision is demonstrated, wire only incremental failure semantics; otherwise retain a report artifact.

## Branches And Decisions

- **AST rule matches barrel/type-only imports too broadly:** narrow the rule or move that check to the import
  parser. Do not create a large allowlist to rescue a bad rule.
- **ast-grep/tool parser fails:** keep existing rules unchanged and use a deterministic script/report; return to
  Diagnose for the parser instead of editing business code.
- **Current violation count changes during the slice:** stop and re-baseline the changed owner; shared worktree
  mutation invalidates a no-new-edge comparison.
- **A durable statement describes target rather than live code:** label the compatibility window explicitly;
  never present an unfinished cutover as completed fact.
- **A rule finds OAuth callback/BI direct RPC:** route to the compatibility allowlist, not a mechanical rewrite.

## Likely Surprises

- Type-only imports inflate static SCCs.
- Barrel exports make a clean runtime dependency look cyclic.
- Existing package/lock changes and root `vue` file are unrelated shared state.
- A rule may scan tests, `index.ts` or the Problem Details adapter unless globs are explicit.

## Rollback / Forward-fix

- Remove or disconnect only the new rule/script; preserve report evidence and durable decisions.
- Downgrade a noisy blocking rule to report-only while its fixture is corrected.
- Never “fix” a false positive by widening domain public exports or moving business logic into controllers.

## Stop Conditions

- Owner conflict, product-semantic change, rule precision not demonstrable, or unrelated worktree drift in owned
  paths. Any of these returns the slice to Solidify/Diagnose.

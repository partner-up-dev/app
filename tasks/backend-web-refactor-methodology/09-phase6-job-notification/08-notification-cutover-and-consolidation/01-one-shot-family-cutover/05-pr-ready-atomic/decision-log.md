# `6-3.1e` Decision Log

| ID | Decision | Exit proof |
| --- | --- | --- |
| `6-3.1e-D1` | `PartnerRequest.readyCycleId` is the durable identity of one actual entry into READY. It changes only inside the named READY transition, remains through later non-READY status for history, and is current only when paired with status READY or ACTIVE. | A later READY re-entry has a different payload/key/cause and an old task skips with a cycle mismatch. |
| `6-3.1e-D2` | Manual and temporal READY writers use a PR-owned serializable, row-locked transaction port rather than a generic cross-domain transaction helper or a post-commit scheduler. | An injected Notification writer failure leaves status/cycle/Jobs/Opportunities unchanged for both modes; concurrent winners produce one cycle. |
| `6-3.1e-D3` | PR supplies only a transaction-local active roster and the READY cycle. Notification owns source filtering for active user, OpenID and available `PR_READY` credit, then derives private once-per-cause Job identity. | Exact source-eligible recipients receive one generic task sharing `partner_request:<prId>:ready:<cycle>`; PR passes no Job/provider/credit settings. |
| `6-3.1e-D4` | Generic `pr.ready` payload includes `{ prId, readyCycleId }`; dispatch requires current PR READY/ACTIVE with that exact cycle and current active membership before channel work. | READY → ACTIVE succeeds; state reversal, re-entry with another cycle, recipient exit or missing PR skip before send/consumption. |
| `6-3.1e-D5` | Generic PR-ready credit is a limited channel opportunity: accepted sends decrement credit while preserving preference; only known WeChat permission revocation clears both. | Final accepted generic credit leaves opt-in true; a later zero-credit task skips; `43101` clears preference and credit. |
| `6-3.1e-D6` | New source writes use only `notification.send.v1`; no new Opportunity or delivery persistence is created. The old concrete handler, payload decoder and cancel prefix remain a bounded legacy drain. | Static inventory has no concrete creation caller, while old handler registration remains and generic scenarios see no Opportunity. |
| `6-3.1e-D7` | This atomic vertical preserves the current broad manual status endpoint rather than quietly redesigning the whole PR state graph. READY is idempotent; any actual compatible manual entry receives a fresh cycle. The creator check moves before temporal refresh. | Existing status API surface remains available; a non-creator direct READY request cannot mutate state through refresh before `403`; later lifecycle-graph work remains explicit. |
| `6-3.1e-D8` | Existing READY/ACTIVE PRs receive a backfilled cycle in the forward migration but no retroactive notification. | Migration check passes and no task/opportunity is created for backfilled rows. |

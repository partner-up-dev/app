# `6-3.2c-3` Rehearsal

- The browser scenario must wait for a real rendered thread sentinel before
  treating an ACK response as visible-route evidence; a request listener alone
  could accidentally accept a pre-render path.
- Scenario setup may use backend builders for durable PR/participant/option
  state. The action under test remains browser route navigation, while a DB
  probe is limited to held/released/reopened reservation proof.
- Existing legacy rows are not required to be generated by the new system
  scenario. A narrow backend overlap fixture is cheaper and more precise for
  proving that `/read-marker` does not touch the generic window.
- A transient client retry is best proven in happy-dom with a controlled first
  rejection; production system verification should not inject timing-dependent
  transport failure.

# Phase 8 / `8-0` Read-only Rehearsal

## Information Before Delegation

1. Freeze `HEAD`, dirty paths and the Phase 3 fitness baseline.
2. Give each auditor a disjoint question and forbid edits.
3. Require exact paths, reproducible counts and interpretation limits.
4. Keep task-packet history, durable truth and current source as separate
   evidence classes.

## Likely Branches

- A count improves while owner span worsens: reject the count as an objective.
- A historical finding disappears: classify the baseline item as stale, not as
  proof that the whole owner family is healthy.
- A new finding is caused by a ratified semantic transaction port: classify it
  against the exception protocol before proposing cleanup.
- A task packet says work is pending while source/history proves it complete:
  record control-plane drift and preserve the historical evidence context.
- An external proof plan relies on diagnostics retired in Phase 7: redesign the
  evidence method or defer the claim; do not restore pseudo-observability.
- A dead-code/security report finding has no owner or removal proof: keep it
  report-first.
- A performance smell has no request-count/query-plan baseline: defer mutation
  and define the measurement first.
- Independent Node/Oxc/quality-gate state overlaps a command: stop before
  writing or staging it.

## Root Validation

- rerun the architecture-fitness reporter twice and compare output;
- sample every high-priority finding directly in source;
- verify cross-auditor claims do not assign one fact to two owners;
- verify each proposed slice has a bounded owner, behavior invariant and cheap
  proof; and
- leave disputed findings as explicit questions rather than manufacturing a
  Phase 8 task.

# Claim Realization Matrix

## Layering Rule

PRD says which product behavior must hold. Product TDD says which unit owns state, command boundaries, transport, and frontend/backend coordination.

This file maps PRD claims to technical realization without redefining product claims.

| PRD claim | Realization focus | Backend realization | Frontend realization | Coordination note |
| --- | --- | --- | --- | --- |
| Claim 1. Lightweight Intent Can Become A Stable Collaboration Object | object formation, creation, persistence | natural-language and structured PR creation APIs; draft/publish lifecycle; persisted `PartnerRequest` state; PR place, route, time-window, status, and current creator authority | home and `/pr/new` entrypoints; natural-language and structured creation flows; publish orchestration; created-PR handoff | backend owns created object semantics; frontend owns entry UX and command handoff |
| Claim 2. Discovery And Authoring Views Can Vary Without Forking PR Semantics | contextual discovery on one durable PR model | single PR lifecycle and persistence; `PR.type`-selected behavior; `/prd` authoring handoff; Form Mode recommendation; one persisted list/card candidate contract | `/prd` PR Discovery page, Form/Card/List views, PR Authoring handoff, and PR detail entry surfaces | PR Discovery views and ordinary Authoring share one PR model; all-zero view ratios fall back to LIST |
| Claim 3. Collaboration Must Remain Distributable And Re-Enterable | share, revisit, history, and route re-entry | canonical PR routes; detail-payload share metadata; share/meta endpoints; public config; session restoration support | route-scoped share orchestration; share UI; route navigation; `/me`; `/pr/mine`; history and revisit surfaces | backend owns canonical entity and share metadata; frontend owns active share session and replay |
| Claim 4. | Claim 5. Identity Should Progress With Commitment Instead Of Blocking Discovery | lightweight-to-stronger identity path | anonymous UUID session restore; authenticated flows; OAuth/bind; token rotation; role and identity-gated command policy | auth bootstrap; local storage continuity; OAuth redirects; pending action resume; identity escalation UX | bearer token plus OAuth handoff cookie contract must stay coherent |
